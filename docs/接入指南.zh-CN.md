# 接入指南

[English](./integration-guide.md)

本文从开源使用者视角说明如何把 `hongxunpan/eloquent-query-dsl` 接入到基于 Eloquent 的应用中。

本包只提供查询构建能力。结果解析、分页执行、response envelope、授权、租户与业务错误处理仍由应用侧负责。

---

## 1. 安装

发布到 Packagist 后使用：

```bash
composer require hongxunpan/eloquent-query-dsl
```

稳定 tag 前可用 VCS repository 或 path repository 评估，并锁定明确 commit 或 tag。生产环境不要依赖浮动 `dev-main`。

---

## 2. 为每个资源定义查询能力

在拥有列表接口的应用 resource / service 附近创建 definition。

```php
use HongXunPan\EloquentQueryDsl\Definition\DslQueryDefinition;

$definition = DslQueryDefinition::make('article')
    ->allowSearch(['title', 'summary'])
    ->allowKeywordSearch('keyword', ['title', 'summary'])
    ->allowFilter([
        'status' => 'string',
        'category_id' => 'integer',
    ])
    ->allowBetween(['published_at'])
    ->allowSort(['published_at', 'id'])
    ->defaultSort('id', 'desc')
    ->strict();
```

建议：

- 只开放这个资源真正安全且有用的字段；
- 对公开 API 默认使用 `strict()`，除非正在兼容旧协议；
- 授权、租户隔离和业务默认 scope 留在 definition 外；
- 不把 raw SQL 表达式当字段名传入。

---

## 3. 以普通数组传入请求参数

默认协议使用 `query` 包裹和 `page` section：

```php
$params = [
    'query' => [
        'search' => ['keyword' => '校友'],
        'filter' => ['status' => 'published'],
        'between' => ['published_at' => ['2026-01-01', '2026-12-31']],
        'sort' => ['published_at' => 'desc'],
    ],
    'page' => ['page' => 1, 'limit' => 20],
];
```

如果你的框架 request 不是数组，请先在应用 adapter 中转成数组，再调用 Query DSL。

---

## 4. 把 DSL 应用到 Builder

```php
use HongXunPan\EloquentQueryDsl\QueryDsl;

$result = QueryDsl::for(Article::query(), $definition)
    ->from($params)
    ->apply();

$builder = $result->builder();
$pagination = $result->pagination();
```

此时 search / filter / between / sort 已作用到 Builder。本包自身不需要执行 SQL。

---

## 5. 应用侧执行分页

```php
$pagination = $result->pagination();

$total = (clone $result->builder())->count();
$items = $result->builder()
    ->forPage($pagination->page(), $pagination->limit())
    ->get();

return [
    'page' => [
        'page' => $pagination->page(),
        'limit' => $pagination->limit(),
        'total' => $total,
    ],
    'list' => $items,
];
```

上面的响应结构只是示例。本包不会定义它。

---

## 6. 保留现有公开参数名

当 API 已有稳定参数名时，用 `DslInputMap` 做映射。

```php
use HongXunPan\EloquentQueryDsl\Input\DslInputMap;

$inputMap = DslInputMap::make()
    ->filter('where')
    ->sort('order_by')
    ->page('page')
    ->limit('per_page')
    ->arrayInput();

$result = QueryDsl::for($builder, $definition)
    ->from([
        'where' => ['status' => 'published'],
        'order_by' => ['published_at' => 'desc'],
        'page' => 1,
        'per_page' => 20,
    ], $inputMap)
    ->apply();
```

轻量旧接口可使用 `flatInput()`：

```php
$inputMap = DslInputMap::make()
    ->flatInput()
    ->search('keyword')
    ->filterPrefix('where_')
    ->sort('sort')
    ->page('page')
    ->limit('per_page');
```

---

## 7. 通过 normalizer 接入应用校验

如果 filter 需要 trim、枚举转换、required 校验或类型转换，实现 `DslFilterNormalizer`。

```php
$result = QueryDsl::for($builder, $definition)
    ->from($params)
    ->filterNormalizer(new ProjectFilterNormalizer())
    ->apply();
```

normalizer 只应把应用校验结果转成 `DslNormalizedFilterSet`，不应让 Query DSL 依赖你的 HTTP 层、响应 helper 或异常类。

---

## 8. 显式接入 relation 查询

```php
$definition = DslQueryDefinition::make('article')
    ->relation('author', 'author')
    ->allowFilter(['author.name'])
    ->allowSearch(['title'])
    ->strict();
```

relation 查询必须显式声明，避免隐藏 join。core 不支持 relation sort；如确需 join / group 语义，请在资源级 adapter 中实现。

---

## 9. 应用侧处理错误

Query DSL 会针对非法 definition 或非法查询输入抛出 Query DSL 异常。应用应在边界层捕获，并翻译成项目自己的响应格式。

不要要求本包理解：

- HTTP status 约定；
- 本地化错误 envelope；
- 业务异常类；
- 日志或链路追踪系统。

---

## 10. 推荐接入路径

1. 选择一个 search / filter / sort 重复逻辑较多的高价值列表接口。
2. 只为当前允许字段建立 `DslQueryDefinition`。
3. 如需保留公开参数形态，用 `DslInputMap` 映射。
4. 只有默认值处理不足时才补 `DslFilterNormalizer`。
5. 在应用侧执行分页和响应包装。
6. 为输入条件、SQL、bindings 与实际结果集补 regression。
7. 再把同样的 definition 风格推广到其他列表接口。
