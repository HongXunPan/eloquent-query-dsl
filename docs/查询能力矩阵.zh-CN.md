# 查询能力矩阵

[English](./query-capability-matrix.md)

本文是 `hongxunpan/eloquent-query-dsl` 的查询能力真相源，用于说明每类能力当前是否已支持、是否属于 adapter、是否暂不受理，以及不受理原因。

README 只保留入口说明；能力状态、语义和规划批次以本文及对应版本 tag 为准。

---

## 1. 状态标记

| 标记 | 状态 | 含义 |
| --- | --- | --- |
| ✅ | 已支持 | 当前 core 已实现，并应有测试覆盖 |
| 🟡 | 计划中 | 已进入后续路线，默认准备补到 core |
| 🔵 | Adapter | 需求合理，但不属于 shared core，应由框架 / 项目 adapter 承接 |
| ⛔ | 不受理 | 与本包边界冲突，未来默认也不接 |
| ⚪ | 待评估 | 暂未承诺，等待真实场景或 issue 推动 |

---

## 2. 已支持能力

| 状态 | 能力 | 分类 | 输入形态 | 是否改 Builder | 批次 | 原因 / 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| ✅ 已支持 | `DslQueryDefinition::make()` | definition | 主实体名 | 否 | 已支持 | 查询能力声明入口；主实体名走安全 identifier 校验 |
| ✅ 已支持 | `relation(entity, relation)` | definition | relation path 映射 | 否 | 已支持 | 用于 relation search / filter 的 `whereHas` 映射；支持 Eloquent 点号路径，路径每段走安全 identifier 校验 |
| ✅ 已支持 | `allowSearch()` | search | `search[field => value]` | 是 | 已支持 | 字段级 search；多个字段默认 AND；空字符串忽略 |
| ✅ 已支持 | `searchRightLike()` | search | 字段列表 | 是 | 已支持 | 将指定 search 字段改为 right-like 语义 |
| ✅ 已支持 | `allowKeywordSearch()` | search | 一个输入字段 + 多个目标字段 | 是 | 已支持 | OR 分组命中多个主实体字段；当前不承接 relation OR 搜索 |
| ✅ 已支持 | `allowDerivedSearch()` | search | callable handler | 是 | 已支持 | 使用侧显式承接复杂搜索逻辑；handler 仍应避免不安全 SQL |
| ✅ 已支持 | `allowFilter()` | filter | `filter[field => value]` | 是 | 已支持 | 单值转 `where`，数组转 `whereIn`，空值忽略，`0` / `false` 有效 |
| ✅ 已支持 | `DslFilterNormalizer` | filter | payload + rules | 间接 | 已支持 | 接入项目 validator / normalize，shared core 只依赖中性 DTO |
| ✅ 已支持 | `allowDerivedFilter()` | filter | rule map | 是 | 已支持 | 适合 null / not-null / has relation 等派生筛选 |
| ✅ 已支持 | `allowDerivedFilterHandler()` | filter | callable handler | 是 | 已支持 | 使用侧承接自定义 filter 行为，命中后不再生成普通 where |
| ✅ 已支持 | `allowBetween()` | between | `[start, end]` | 是 | 已支持 | 应用 `whereBetween`；不解释业务时间闭区间策略 |
| ✅ 已支持 | `allowSort()` | sort | sort item list | 是 | 已支持 | 支持显式多字段排序；顺序必须由数组项顺序表达，不支持字符串或 map 简写 |
| ✅ 已支持 | `sortAscOnly()` / `sortDescOnly()` | sort | 字段列表 | 是 | 已支持 | 限制字段排序方向，strict 下非法方向阻断 |
| ✅ 已支持 | `defaultSort()` / `defaultSortMany()` | sort | 字段 + 方向 | 是 | 已支持 | 无显式 sort 时生效；顺序稳定 |
| ✅ 已支持 | derived default sort | sort | filter 命中策略 | 是 | 已支持 | 根据 filter values 选择默认排序，优先于普通 default sort |
| ✅ 已支持 | strict mode | behavior | `strict(true)` | 间接 | 已支持 | 未开放 section / field 或非法输入时阻断 |
| ✅ 已支持 | loose mode | behavior | `strict(false)` | 间接 | 已支持 | 未开放字段或非法 sort direction 默认忽略 |
| ✅ 已支持 | identifier security | security | field / entity / relation | 否 | 已支持 | 普通 identifier 限定为 `[A-Za-z_][A-Za-z0-9_]*` |
| ✅ 已支持 | `DslInputMap` | input | 自定义参数名 | 否 | 已支持 | 不要求使用侧外部参数名固定为 `query.filter` |
| ✅ 已支持 | `DslInputParser` | input | 自定义 parser | 否 | 已支持 | 完全自定义输入解析入口 |
| ✅ 已支持 | flat input | input | 扁平参数 | 否 | 已支持 | 支持 `keyword`、`where_*`、`sort`、`page/per_page` 等外部形态 |
| ✅ 已支持 | `DslPaginationPolicy` | page | policy | 否 | 已支持 | 限制 page / limit / export_limit 事实 |
| ✅ 已支持 | `DslCursorRequest` | cursor | limit + position + direction | 否 | 已支持 | page / cursor 互斥；结构化双向游标，不要求 Base64 |
| ✅ 已支持 | `QueryDslResult` | output | builder + facts | 否 | 已支持 | 返回 Builder、filter values、pagination facts |

## 3. 当前明确不支持或由 adapter 承接

| 状态 | 能力 | 分类 | 原因 / 说明 |
| --- | --- | --- | --- |
| ⛔ 暂不支持 | relation sort | sort | 当前不隐式生成 join / group / select 语义，避免不同项目结果不稳定 |
| 🔵 Adapter | HTTP request 读取 | adapter | 与框架相关，应由项目 adapter 承接 |
| 🔵 Adapter | HTTP response / response envelope | adapter | 本包只返回中性查询事实，不定义 API 响应结构 |
| 🔵 Adapter | `QueryPaginationTrait` | adapter | 属于业务仓分页响应封装，不进入 shared core |
| 🔵 Adapter | 业务异常翻译 | adapter | 本包抛 Query DSL 异常，项目自行翻译为业务异常 / HTTP 状态 |
| 🔵 Adapter | 权限 / 租户隔离 | adapter | 依赖业务用户、权限和数据域，不进入 shared core |
| 🔵 Adapter | 资源字段开放清单 | adapter | 字段清单由业务资源声明，不应沉淀到包内 |
| 🔵 Adapter | projection / DTO 重组 | adapter | 展示投影应由 projection 包或业务 presenter 承接 |
| ⛔ 不受理 | raw SQL 字段字符串 | security | 普通字段字符串不承接表达式；未来若需要 raw，应另开显式 API 与风险标记 |
| ⛔ 不受理 | 多级路径伪装普通字段 | security | `a.b.c`、函数、引号、反引号等默认拒绝 |

## 4. 维护规则

1. 新增 core 查询能力时，必须同步本文、README 入口说明与 regression。
2. 能力从 🟡 计划中变为 ✅ 已支持时，必须补 SQL / bindings / 结果集断言。
3. 能力被判定为 🔵 Adapter 或 ⛔ 不受理时，必须保留原因，避免后续重复讨论。
4. README 只新增矩阵链接，不把完整矩阵搬回 README。
5. 若状态与代码不一致，以当前版本代码和测试为准，并立即修正文档。
