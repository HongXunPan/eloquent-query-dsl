# 发布检查清单

本文档用于 `hongxunpan/eloquent-query-dsl` tag / GitHub Release / Packagist 发布前的固定检查，避免依赖聊天记录或个人记忆。

当前包处于 pre-1.0 阶段；目标版本号应依据实际变更按语义化版本确定，并先回填对应任务单。

## 1. 发布边界

发布前必须确认本包仍只承接 Query DSL shared core：

- 外部输入解析为 `DslQueryInput / DslPageInput`；
- 查询能力声明与字段安全边界；
- `search / filter / between / sort` 读取与应用；
- filter values 与 pagination facts 等中性事实；
- `DslInputParser / DslInputMap / DslFilterNormalizer / DslPaginationPolicy` 等扩展契约。

不得把以下内容带入本包：

- `App\` 命名空间下的业务项目代码；
- `simple-framework` 专属 adapter；
- HTTP response / response envelope；
- 业务异常翻译；
- 业务仓 `QueryPaginationTrait`；
- 旧 DSL compat runtime；
- 业务资源字段开放清单、权限语义或页面返回结构。

## 2. 仓库与分支检查

在子包仓库根目录执行：

```bash
git remote -v
git branch --show-current
git status --short --ignored
```

发布前要求：

- remote 指向 `HongXunPan/eloquent-query-dsl`；
- 发布分支为预期分支，默认 `main`；
- `vendor/`、`composer.lock`、`.idea/` 只能是 ignored，不得进入 staged / commit；
- 不存在未解释的本地临时文件、缓存文件或备份文件。

## 3. 版本与文档检查

发布目标版本前必须检查：

- `CHANGELOG.md` 已存在带发布日期的目标版本段落；
- `README.md` / `README.zh-CN.md` 的能力、边界、CI 命令与 `composer.json` scripts 一致；
- 核心 docs 的中英文版本已互链，且 API 能力、扩展点、接入步骤与 adapter 边界一致；
- `CONTRIBUTING.md` 的验证命令与 CI workflow 一致；
- `SECURITY.md` 已说明安全报告入口与 shared core / 使用侧边界；
- `.gitattributes` 不会把 `vendor/`、`composer.lock`、测试与 CI 配置打进 Composer dist；
- `composer.json.description` 仍优先说明“解决什么问题与边界”，不改成来源故事。

## 4. 容器内质量门禁

共享 Composer 包的 PHP / Composer 验证默认以 `gplus-php-fpm` 容器为真相源。

推荐命令：

```bash
docker exec gplus-php-fpm sh -lc 'cd /data/www/HongXunPan/composer-packages/code/dsl && composer validate --strict && composer quality'
```

等价拆分命令：

```bash
composer validate --strict
composer test
composer analyse
composer cs:check
composer security:audit
```

通过标准：

- Composer metadata strict validate 通过；
- PHPUnit 与 legacy smoke 全通过；
- PHPStan level 8 无错误；
- PHP-CS-Fixer dry-run 与轻量仓库卫生检查通过；
- Composer audit 无安全公告。

## 5. CI 检查

GitHub Actions 必须至少覆盖：

- PHP 8.0 + illuminate/database 9；
- PHP 8.1 + illuminate/database 10；
- PHP 8.2 + illuminate/database 11；
- PHP 8.3 + illuminate/database 12；
- Static analysis / PHPStan level 8。

发布 tag 前要求：

- 最新 `main` push 后 CI 全绿；
- 若本地通过但 CI 失败，优先以 CI 失败证据定位 PHP / Illuminate 矩阵兼容问题，不直接打 tag。

## 6. Packagist 前检查

首次公开发布前检查：

- GitHub 仓库可公开访问；
- `composer.json` 包名、license、homepage、support.source、support.issues 正确；
- `README.md` / `README.zh-CN.md` 已包含安装、推荐接入方式、边界与验证命令；
- API Reference、Integration Guide、Public Contracts、Capability Matrix、Canonical Examples 已具备双语入口；
- `LICENSE` 存在；
- `SECURITY.md` 存在；
- Packagist 若尚未关联 GitHub webhook，发布后需手动触发同步或检查自动同步状态。

## 7. Tag 操作模板

仅在质量门禁和 CI 均通过后执行。

```bash
VERSION=0.4.0
git tag -a "$VERSION" -m "Release $VERSION"
git push origin "$VERSION"
```

若 tag 已创建但未推送且发现问题：

```bash
VERSION=0.4.0
git tag -d "$VERSION"
```

若 tag 已推送到远端，不要擅自删除或重打；应先评估并发布新的更高版本。

## 8. GitHub Release 文案模板

标题：

```text
<目标版本> - Eloquent Query DSL pre-1.0 版本
```

正文：

```markdown
## Highlights

- 提供 Eloquent / Builder 列表查询 DSL core。
- 支持 search / filter / between / sort / page 查询协议。
- 提供字段安全 identifier 校验与分页策略上限。
- 提供中性 filter normalizer 契约，不绑定业务项目 validator。
- 提供 PHPUnit、legacy smoke、PHPStan level 8、PHP-CS-Fixer 与 CI 矩阵。

## Boundaries

- 不包含 backend adapter。
- 不包含 HTTP response / response envelope。
- 不包含 QueryPaginationTrait。
- 不包含业务字段开放清单、权限语义或页面返回结构。

## Verification

- composer validate --strict
- composer quality
- GitHub Actions matrix 全绿
```

## 9. 发布后回填

发布后必须回填：

- `任务/00-任务总览.md` 的目标 ref / tag；
